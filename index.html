Cómo trabajo

Del dashboard al seguimiento

Mi tarea no es reparar la infraestructura. Es detectar rápido, comunicar bien y que ningún incidente quede sin dueño.

  1. 01

    Monitorear

    Observo dashboards y gráficas para controlar el estado de servidores, conectividad y APIs.

  2. 02

    Detectar

    Identifico caídas, anomalías y problemas de disponibilidad, y reúno la información inicial.

  3. 03

    Registrar

    Cargo el incidente en un ticket con el servicio afectado, el síntoma y la hora de inicio.

  4. 04

    Notificar

    Aviso por chat al sector responsable para que el incidente se conozca enseguida.

  5. 05

    Escalar

    Derivo el incidente al equipo que puede analizarlo y resolverlo.

  6. 06

    Dar seguimiento

    Sigo el evento reportado, con foco en la continuidad de los servicios monitoreados.

Simulación

Qué hago cuando aparece una alerta

Elegí una alerta y mirá el circuito completo. Los datos son ficticios: es una demostración de mi forma de trabajar, no un sistema de monitoreo real.

  1. DetectoEl panel de APIs muestra respuestas HTTP 500 sostenidas en la API de turnos.
  2. ValidoReviso desde cuándo ocurre, si el error persiste y si otras APIs o el servidor que la aloja también fallan.
  3. RegistroAbro un ticket con el servicio afectado, la hora de inicio, el síntoma y una captura del panel.
  4. NotificoAviso por chat al sector responsable con el número de ticket.
  5. EscaloDerivo el incidente al equipo de Aplicaciones.
  6. SigoControlo el panel hasta que la API responda con normalidad y actualizo el ticket.
